## 3. Найденные ошибки и риски в коде

1. **Статический материал елей** (`scripts/world/road.gd:237`, `_twig_m`): эпилоги весна/лето ставят ему `snow=0`
   (`chapter5.gd:1263`), конец игры перезагружает сцену — в следующей игре без перезапуска ели могут остаться без снега
   [П по коду; есть сброс в `chapter5.gd:821` — проверить порядок].
2. **«Продолжить» молча начинает новую игру**, если сохранение не прочиталось (`game.gd` ≈286–292), а пролог сам
   сохраняется — после двух контрольных точек старое сохранение потеряно.
3. **`lake_checkpoints.json` и `lake_progress.json` пишутся напрямую**, без временного файла и `.bak` (`game.gd`
   ≈1750, 1857, 2190–2195): при сбое во время записи пропадут дерево выборов и найденные концовки.
4. **Нет миграции формата сохранений** (`v:2`): переименование сцены в новой версии ломает старые сохранения.
5. **Ошибки записи файлов не проверяются.**
6. **BootGuard** (`scripts/boot_guard.gd`): снятие задачи, выключение ПК или долгая сборка шейдеров считаются вылетом —
   качество тихо падает до «Низкого», потом до совместимого режима; счётчик не сбрасывается.
7. **Настройки импорта текстур не в git** (`.gitignore:6`): чистая сборка без `tools/lake/vram_textures.py` и
   `tex_quality.py` снова даст ≈3,3 ГБ видеопамяти — та самая причина вылета на встроенной Radeon.
8. **Модели, текстуры и шрифты игры не в git — главный технический риск.** `godot/lake/.gitignore:3` исключает всю
   папку `assets/` (в git из неё 0 файлов; на диске 347 МБ: герои 85 МБ, места и машины 155 МБ, Poly Haven 104 МБ).
   В git — только скрипты, которые их делают (`tools/lake/fetch_assets.py`, `build_chars.sh`, Blender-скрипты мест) и
   звук (977 `.ogg`). Восстановить ровно ту же игру с чистого клона нельзя: нужны Blender 4.5 с MPFB2 и пакетами
   MakeHuman, скачивание Poly Haven, модели и движения из Hush Till Six, а симуляция ткани каждый раз даёт немного
   другую одежду. Сейчас текущие модели и риги есть **только в этом облачном окружении и внутри сборок 1.2**; `.blend`
   героев тоже не хранятся. Перед доработкой — архив `assets/` с датой и контрольными суммами (Adobe или Google Drive
   владельца) или Git LFS (`DEVELOPMENT_ROADMAP.md`, 0.6).
   **Сделано 4 ноября:** архив `WhatTheLakeKeeps_assets_backup_2026-11-04.zip` (1208 файлов, 360 МБ, в архиве 263 МБ,
   вместе с файлами `.import`) — в Adobe Creative Cloud владельца, папка WhatTheLakeKeeps (размер на сервере совпал до
   байта); каждый файл архива сверен с оригиналом по SHA-256 (1208 из 1208); список сумм — `assets_backup_2026-11-04.sha256`.
   **Восстановление из облачной копии не проверено** (скачать её отсюда нельзя) — до проверки у владельца копия считается
   непроверенной; как проверить — `EDITOR_DECISIONS_2026-11-04.md`, последний раздел.

## 4. Сохранения

- `user://lake_save.json` = `{v:2, scene, flags, lang, clock}`; запись: временный файл → прошлое — в `.bak` →
  подмена; при испорченном файле берётся `.bak` (проверено автотестом D 4/4).
- Контрольных точек — 36 на 324 сцены (в гл.4 — 6 на 78); внутри главы состояние восстанавливает `ChN.restore()` по
  флагам. Риски — пункты 2–5 раздела 3.

## 5. Производительность (по коду; цифры на настоящем железе не мерились)

1. Снег — `CPUParticles3D` до 7000 частиц на процессоре.
2. Два полноэкранных шейдера в интерфейсе (виньетка, помехи) рисуются всегда, даже при силе 0 (`hud.gd` ≈126–169) —
   лишняя заливка на телефоне.
3. Лицо каждого героя каждый кадр создаёт новые словари (`actor.gd` ≈1209–1330).
4. Посадка (`Seats._top`, `seats.gd` ≈21–75) перебирает треугольники сеток на GDScript — возможен рывок при посадке.
5. Лист дневника рисуется попиксельно — 614 тыс. `set_pixel` (`hud.gd` ≈359–371) — рывок при открытии.
6. Деревня — 604 сетки, заправка — около 20 источников: много вызовов отрисовки; в Compatibility на телефоне — до
   16 источников на объект, многопроходно.
7. В облаке один запуск Forward+ съедает ≈6 ГБ оперативной памяти (программная видеокарта считает на процессоре —
   не показатель для ПК, но признак тяжёлых данных).
