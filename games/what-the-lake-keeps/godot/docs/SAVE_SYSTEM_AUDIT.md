# WHAT THE LAKE KEEPS — сохранения: аудит и исправления

1–2 ноября, главное ТЗ (этап 14). Код — `scripts/game.gd` (`_save`, `_load_save`, `_read_save`, `_resume_at`),
восстановление по главам — `ChN.restore()`; проверки — `scripts/dev/input_test.gd` (`--savetest A…H`). Доработка 4 ноября (после аудита, этап 2 согласованного
плана) — S-11…S-14.

## 1. Как устроено
* Контрольная точка — сцена с `"save": true` (в начале сцены, до её начислений флагов): `user://lake_save.json` =
  `{"v": 3, "scene", "flags", "lang", "clock"}` (v 2 и без `v` читаются так же). «Продолжить» сбрасывает флаги к значениям из данных, накладывает
  сохранённые, восстанавливает видимое по флагам (`_resume_at` + `ChN.restore`) и проигрывает сцену с начала —
  ничего не начисляется второй раз (проверка B).
* Отдельно: `user://lake_checkpoints.json` (дерево выборов, «переиграть отсюда»), `user://lake_progress.json` (карта глав
  и журнал концовок), `user://lake_settings.cfg` (настройки). С 4 ноября все три JSON-файла пишутся одинаково
  (`_write_json`): временный файл → прошлый в `.bak` → подмена; читаются с запасной копией (`_json_file`).

## 3. Проверки
Результаты — `FINAL_QA_REPORT.md` §4 (запуски `--inputtest --savetest A…E` один за другим, общий `user://`):
* A — сохранение на входе в пост = флаги на входе; после выбора — сохранение `c2_s4` с выбором;
* B — «Продолжить»: флаги как при сохранении, без повторного начисления;
* C — раннее сохранение → другой выбор: следов первого нет;
* D (новая) — испорченный основной файл → запасная копия `c5_s4`: Хейл, санитар и седан у берега, лёд, часы из сохранения;
* E (новая) — `c3_s6` с `danny_lost`: Дэнни не появляется в доме; младенец на руках;
* F (4 ноя) — испорчены и сохранение, и копия: «Продолжить» показывает вопрос, файл не тронут, «Назад» — меню,
  «Начать новую игру» — игра с начала (5/5);
* G (4 ноя) — «Новая игра» при сохранении: вопрос, сразу выбрано «Назад», Enter — назад, сохранение то же; «Начать

* H (4 ноя) — испорченные прогресс и контрольные точки читаются из `.bak`; после записи файл целый, временного нет (4/4).

## 4. Ограничения
* «Продолжить» после ТИТРОВ повторяет последнюю концовку (последняя контрольная точка — сама концовка или берег);
  другие концовки — через «Дерево выборов → переиграть отсюда».
* Новая игра после «Начать заново» перезаписывает сохранение (пролог — контрольная точка); удаления прогресса в меню нет.
* Внутреннее состояние глав (`c2…c5`: что лежит на столе, горит ли печь) не сохраняется — восстанавливается постановкой
  сцены с начала; поэтому контрольные точки стоят только в начале сцен.

## Мастер-промпт: главы 2–5 (3 ноября)
* Новых контрольных точек нет: новые сцены (кафе, буран, деревня, дом, буханка, остановка, санаторий, дача) лежат
  между прежними точками и сохраняются ими. Новые отметки (`c2_…`–`c5_…`, `ev_archive`, `ev_letter`) — обычные флаги
  в сохранении; старое сохранение без них загружается (недостающие флаги берутся из данных глав со значением 0).
* «Продолжить» с точки внутри главы 4 после заезда в санаторий: обстановку ставит `Ch4.restore` (дорога, день, все в
  буханке; для `c4_sana` — так же, затем сцена сама ставит буханку у ворот).
* Проверка с середины главы (`--scene … --restore`) идёт тем же путём, что «продолжить» (`_resume_at`).
* **Найдено и исправлено: запасная копия не создавалась.** `game.gd` (`_save`) копировал прошлое сохранение в `.bak`
  по относительному имени — `DirAccess.copy` его не находил («Failed to open 'lake_save.json'»), копии не было, и
  обещанное «файл испорчен — возьмём запасную» на деле не работало (проверка D это не ловила: она сама пишет `.bak`).
  Теперь пути полные (`copy_absolute`, `remove_absolute`, `rename_absolute`): после проверки B в `user://` лежат
  `lake_save.json` и `lake_save.json.bak`.
* Проверки A и C проходят новый разговор в дороге после поста (`c2_s3_road`, темы без таймера) — `input_test.gd`
  выбирает «Помолчать». Итоги запусков — `FINAL_QA_REPORT.md` §0.
