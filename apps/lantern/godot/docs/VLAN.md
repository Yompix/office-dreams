# LANTERN 2.0 — «Любые игры»: виртуальная локальная сеть

Цель: любые игры с игрой «по локальной сети» (LAN) работают через интернет — как Radmin VPN / Hamachi / ZeroTier.
ПК ↔ ПК, Android ↔ Android, ПК ↔ Android (если сама игра умеет кроссплей).

## 1. Выбор ядра

### Вариант A — встроить EasyTier
- Rust, P2P + ретрансляторы, Windows через Wintun, есть Android-приложение на VpnService.
- Лицензия: в задаче указана Apache-2.0; по моей памяти у EasyTier **LGPL-3.0**. Проверить из контейнера не удалось
  (github.com закрыт прокси, 403) — до встраивания нужно сверить. Для LGPL пришлось бы поставлять его как отдельный
  заменяемый файл и выполнять условия LGPL.
- Бинарники и Android-ядро скачать не удалось (тот же 403); собрать из исходников — Rust + Android NDK, несколько ГБ —
  при ~600 МБ свободного диска невозможно.
- Главное — безопасность: у EasyTier свой протокол и свои узлы-ретрансляторы. Наш relay живёт внутри сайта на Railway
  (Node, только WebSocket, без UDP). Пришлось бы держать на Railway отдельный процесс EasyTier и доверять его настройкам
  (exit-node, subnet proxy), а условие «relay пересылает только трафик между участниками и ничего в интернет» проверять
  в чужом коде.

### Вариант B — свой туннель L3 (ВЫБРАН)
- Windows: **Wintun** (подписанный драйвер WireGuard LLC, `wintun.dll` можно распространять — лицензия в архиве) +
  маленький помощник `lantern-net.exe` (Go, без сторонних библиотек, 2,5 МБ): создаёт адаптер «LANTERN», ставит адрес,
  MTU, метрику и правило брандмауэра. Пакеты отдаёт приложению по UDP 127.0.0.1 с одноразовым ключом.
- Android: `LanternVpnService` (наш Java, VpnService) — интерфейс 10.88.x.y/24, пакеты — в приложение тем же протоколом.
- Linux: тот же `lantern-net` с `/dev/net/tun` (им же гоняются автотесты).
- Сеть, P2P и relay — **одна** реализация на GDScript (`scripts/vnet/vnet.gd`) для всех платформ.
- Relay — наш (`relay/vnet.js`): читает только заголовок IPv4 и пересылает **только участникам своей сети**.

Почему B: встаёт в нашу инфраструктуру (тот же WSS-relay на Railway, коды из 8 цифр/QR, профили, баны), полностью
наш контроль безопасности, маленький размер (+3 МБ к Windows-архиву, +0 к APK), всё проверяется автотестами здесь.
Цена: P2P проще, чем у EasyTier (нет UPnP/IPv6/TURN), шифрование P2P — только подпись (см. §5).

## 2. Как устроено

```
игра ⇄ адаптер (Wintun / VpnService / tun) ⇄ UDP 127.0.0.1 ⇄ LANTERN (VNet, свой поток)
     ⇄ relay WSS /lantern/ws (всегда)  или  напрямую UDP P2P (если пробили NAT)
```
- Адреса: 10.88.O.n/24, O — случайный для каждой сети (1–254), создатель — .1. Сеть живёт, пока в ней кто-то есть
  (+5 мин на возврат после обрыва/перезапуска relay).
- Вход — номер из 8 цифр или код из 6 знаков, ссылка `https://…/lantern/j/<номер>` и QR (страница открывает
  `lantern://net?code=…`). Пароль, места (16, у Plus — 32), «Видна всем» → «Найти игроков» (`GET /lantern/vnets?game=`).
- Перезапуск relay (выкладка на Railway): участники возвращаются сами с подписью сети (HMAC секрета комнат) и прежним IP.

### Протокол (WebSocket, текст — JSON)
| клиент → relay | смысл |
|---|---|
| `vnet_create {name, game, public, password, cap, token, nick}` | создать сеть |
| `vnet_join {code, password, token, nick}` (+`resume, peer, ip, num, octet, owner, owner_uid`) | войти / вернуться |
| `vnet_sig {to, d:{c:[[ip,port]…]}}` | кандидаты P2P (≤1 КБ, ≤120/мин) |
| `vnet_ping/vnet_pong {to, ts}` | пинг между участниками (≤8/с) |
| `vnet_chat {text}`, `vnet_react {id, e}` | чат сети и реакции (8 эмодзи) |
| `vnet_kick {peer, ban}`, `vnet_meta`, `vnet_end` | только создатель |
| `vnet_list {game}` | открытые сети |
Ответы: `vnet` (адрес, ключ, участники), `vnet_peer`, `vnet_pings`, `vnet_sig`, `vnet_chat`, `vnet_react`, `vnet_meta`, `error`.
Бинарный кадр = сырой IPv4-пакет.

### Безопасность relay (`relay/vnet.js`, тест `relay/test_vnet.js`)
- Пакет принимается только от участника сети и только с **его** адресом отправителя (подделка — в мусор).
- Адресат: участник этой же сети (10.88.O.n), широковещательный 10.88.O.255 / 255.255.255.255, групповой 224.0.0.0/4.
  Всё остальное (интернет, чужие сети, IPv6) — отбрасывается: relay не прокси.
- Размер ≤ 1500 байт; лимиты: 4 МиБ/с и 4000 пакетов/с на участника, 80 широковещательных/с (их relay размножает),
  16 МиБ/с на сеть; зависший получатель (>4 МиБ в очереди) просто теряет пакеты, как в настоящей сети.
- Вход: лимит попыток с IP (общий с комнатами), пароль (SHA-256 с солью), баны по аккаунту/IP, коды/номера не
  пересекаются с комнатами Minecraft. Переменные: `VNET_MAX`, `VNET_MAX_MEMBERS`, `VNET_MEMBER_BPS`, … (vnet.js, VCFG).

### P2P
- Каждый клиент держит UDP-сокет; публичный адрес — STUN (stun.l.google.com, stun.cloudflare.com), плюс свои
  локальные адреса (та же Wi-Fi сеть). Кандидаты — через relay только участникам сети.
- Оба шлют «стук» (каждые 250 мс, 12 с) — кто ответил, с тем личные пакеты идут напрямую. Пропал на 7 с — снова relay.
- Кадр P2P: `"LV" · тип · peer · HMAC-SHA256(ключ сети)[0:8] · данные`; внутри проверяется адрес отправителя.
- Широковещательные всегда через relay. Симметричный NAT (часто — мобильный интернет) не пробивается — работает relay.
- P2P можно выключить: `Cfg [net] p2p=false` (адрес не раскрывается участникам).

## 3. Windows: права и установка
- «Подключить» в первый раз: окно UAC → `lantern-net.exe --install` регистрирует задачу планировщика «LANTERN Net»
  (наивысшие права, только для этого пользователя). Дальше — без UAC: приложение пишет
  `%LOCALAPPDATA%\LANTERN\net-request.json` (порт, ключ, IP, проверяются помощником: только 10.88.x.y) и запускает задачу.
  Задача не сработала за 25 с — дальше запуск напрямую с UAC каждый раз.
- Адаптер «LANTERN» (постоянный GUID — Windows не плодит «Сеть 2, 3…»), метрика 1 (широковещательные 255.255.255.255
  уходят в LANTERN — так делают Hamachi/Radmin), правило брандмауэра «LANTERN virtual LAN»: входящие только с 10.88.0.0/16.
- Убрать всё: `lantern-net.exe --uninstall` (от администратора).

## 4. Android
- Системный запрос «Разрешить VPN?» — один раз. Маршруты: только своя сеть /24, 255.255.255.255/32 и 224.0.0.0/4
  (если Android их примет); остальной интернет идёт мимо. LANTERN сам исключён из VPN (без петель).
- Ограничения Android: одновременно работает **один** VPN (наш выключит другой); поиск игр «по Wi‑Fi» многие игры
  делают широковещанием в интерфейс Wi‑Fi, а не в VPN — тогда игру не видно в списке, и нужно вводить IP друга
  (Terraria, Mindustry, Minecraft «Добавить сервер»). На настоящем телефоне это **не проверено**.
- Google Play: VpnService разрешён, если VPN — основная функция приложения; при выпуске заполнить декларацию VPN
  в Play Console (docs/PLAY_BILLING.md §6). Служба переднего плана `specialUse` уже обоснована (1.3).

## 5. Честные ограничения
- Игры с античитом уровня ядра или с проверкой сети (Valorant/Vanguard, EAC, BattlEye) и игры только с официальными
  онлайн-серверами так не работают. Это не обход, а обычная «локалка».
- Пакеты через relay идут по TLS (wss). P2P-пакеты подписаны, но **не шифруются** (как в обычной LAN) — пароль игры
  в открытом виде по P2P не передавайте.
- Задержка через relay = до Railway и обратно (регион relay — в `/lantern/healthz`); P2P — напрямую.
- Нет IPv6 внутри сети, нет TURN-серверов, нет UPnP.

## 6. Проверка
- `cd apps/lantern/relay && node test_vnet.js` — relay: вход/пароль/список, широковещание и личные пакеты,
  отбрасывание подделок/интернета/IPv6/больших, P2P-сигналы, пинг, чат/реакции, бан, возврат после перезапуска.
- `apps/lantern/godot/tests/vnet_e2e.sh` (root, Linux) — два LANTERN + два настоящих TUN в своих network namespace:
  поиск сервера широковещанием (10.88.x.255 и 255.255.255.255), ответ лично, TCP-вход; `P2P=1` — то же напрямую.
- Wine: `lantern-net.exe --version/--check` (Wintun грузится), приложение входит в сеть; настоящий адаптер под Wine
  не создаётся (нет драйвера) — проверять на настоящем Windows.
